# Установка

Инспектор не слушает сеть: он подписчик очереди на шине. Ни адреса, ни Service ему не нужно, и
добавление копии не трогает ни узел защиты, ни конфигурацию. Обычно его поднимает фундамент
установки (`placitum-core`).

## Что нужно рядом

| Компонент | Обязателен | Зачем |
| --- | --- | --- |
| NATS | да | очередь `waf.req.counter`, аудит, журнал, поколение профилей |
| Redis: внутренний | да | корзины `cnt:bkt:*`; без него суд отвечает `verdict: error` |
| Redis: обменник | для осей `sess`, `user` и правил по телу | снимок запроса и ответа по локатору |
| `geo` | для осей `asn_net`, `asn_router` и записи `net`/`asn` | анонсы и номер системы по адресу |
| Контроллер | да | шлёт профили и общую секцию счётчиков поколением |

## Переменные

| Переменная | По умолчанию | Что |
| --- | --- | --- |
| `NATS_URL` | `nats://127.0.0.1:4222` | шина |
| `REDIS_URL` | из `inspector.conf` | обменник: снимок запроса и ответа |
| `REDIS_INTERNAL_URL` | из `inspector.conf` | внутренний Redis: корзины |
| `WAF_COUNTER_SUBJECT` | `waf.req.counter` | подписка; одна на все фазы, ветка по `phase` в сообщении |
| `WAF_COUNTER_NAME` | `counter` | имя в реестре инспекторов и в кадре присутствия |
| `WAF_COUNTER_PROFILES` | `./profiles` | каталог профилей из образа; в образе `/app/profiles` |
| `WAF_COUNTER_DATA` | `<профили>.applied` | куда раскатка кладёт применённое поколение |
| `WAF_COUNTER_GEO_ADDR` | пусто | кодер гео (`host:port`). Пусто — оси `asn_net`/`asn_router` молчат, остальные работают |
| `WAF_COUNTER_GEO_TIMEOUT` | `500ms` | ожидание кодера в бюджете сообщения |
| `WAF_COUNTER_GEO_NEG_MAX` | `0` | потолок отрицательного кэша кодера; `0` — умолчание |
| `WAF_COUNTER_LOG` | `info` | стартовый уровень журнала; живьём его переставляет панель |
| `WAF_COUNTER_VERSIONS` | `2` | версии схемы сообщения, которые процесс принимает |
| `WAF_COUNTER_WORKERS` | число ядер | воркеры пула |
| `WAF_COUNTER_QUEUE_DEPTH`, `_QUEUE_FULL`, `_QUEUE_EXPAND` | `256`, `drop`, `off` | очередь; то же через `inspector.conf` |
| `WAF_COUNTER_RESERVE_MS`, `_MIN_BUDGET_MS` | `2`, `2` | запас бюджета на ответ и минимальный бюджет, ниже которого не берётся |
| `WAF_COUNTER_RELOAD_EVERY` | `1s` | опрос отпечатка каталога профилей |
| `WAF_COUNTER_CONF` | `./inspector.conf` | путь к файлу очереди и адресов Redis |

`inspector.conf` в образе называет оба Redis по именам сервисов compose; окружение его
перекрывает.

## Docker Compose

```yaml
services:
  inspector-counter:
    image: placitum/counter
    scale: 2
    environment:
      NATS_URL: nats://nats:4222
      REDIS_URL: redis://redis:6379
      REDIS_INTERNAL_URL: redis://redis-internal:6379
      WAF_COUNTER_GEO_ADDR: geo:50051
      WAF_COUNTER_LOG: info
    depends_on: [nats, redis, redis-internal]
```

## Маршрут

Счётчик ставят **раньше** получателей своих действий — капчи, modsec: действия соседям по своей
волне не видны. Фазу ответа включают отдельно, и для неё нужен снимок заголовков ответа:

```nginx
waf_inspector counter subject=waf.req.counter;

location /api/ {
    waf_inspect ip       wave=0 timeout=5ms;
    waf_inspect counter  wave=1 timeout=10ms;            # судит и шлёт действия
    waf_inspect captcha  wave=2 timeout=10ms;
    waf_inspect response counter wave=0 timeout=10ms;    # меряет
    waf_capture response headers;
}
```

Для осей `sess` и `user` маршрут должен снимать заголовки запроса; для счёта совпадений в теле —
превью тела ответа. Размер в килобайтах работает и без тела.

## Проверка после запуска

```sh
docker exec <контейнер> counter-probe --quiet --timeout 1s --uri /healthcheck
```

Проба идёт тем же путём, что боевая инспекция, и отвечает `deny` с пустой корзины — без Redis и
без трафика. В журнале при здоровом старте: подключение к шине, загруженные профили, число
воркеров; дальше кадр присутствия каждые четыре секунды.

## Грабли

- **Отказанные раньше запросы корзин не греют.** До фазы ответа доезжает только то, что клиент
  действительно получил, — поэтому счётчик за отказывающим маршрутом покажет меньше, чем логи.
- **Слепое пятно фазы ответа.** Маршруты, где модуль отдаёт ответ в обход (`sse`, `upgrade`,
  слишком большое тело), не меряются вовсе.
- **Профиль `_probe` едет в образе, а не поколением.** Поколение его не везёт; процесс
  подмешивает его из каталога образа сам, и если это сломать — контейнер станет `unhealthy` при
  полностью живом инспекторе.
